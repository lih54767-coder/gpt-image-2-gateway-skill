# 通过中转站生图并在飞书交付

触发：用户要求用我们的 Image 2 生成或修改图片，并在当前飞书会话看到产物。这是**实际生成/编辑 + 可见交付**，不是只回答文字。

## 制作与验收

1. 按 `gateway-image2.md` 使用 `scripts/image_gen_gateway.py`，由包装入口读取**当前使用者已配置**的中转站 URL 和 API Key，并固定图片模型 `gpt-image-2`。凭据仅在本地私有配置和进程内，不写入命令、脚本正文、聊天或日志。不要因 Hermes 内建 `image_gen` 的配置为空就断言中转站生图不可用，也不要为交付偷偷换成内建工具或 OpenAI 直连。专用入口失败时立即报告；不静默 fallback。
2. 确认输出是非空、可解码的图片文件（PNG/JPEG 等），用 `vision_analyze` 检查主题、人数、文字、人物质感和修改不变量。HTTP 200 或自然语言回复不等于图片产物。改图要以用户指定的成品图为输入；保留人物等不变量，但说明生成式编辑可能轻微重绘整图，不能承诺未修改像素绝对不变。
3. 真人海报优先纪实摄影语言：自然皮肤纹理、不完美细节、真实环境/舞台光、抓拍姿态；避免塑料磨皮、CGI 光晕与过度锐化。无参考图时不能保证真人艺人五官准确。用户未指定演出场次时不编造官方巡演时间/场馆；检查模型额外生成的小字。
4. 若摄影底图满意但模型字体廉价，优先生成**无字、留排版空间的底图**，用真实授权字体做本地确定性排版；验收标题字形、裁切和人脸遮挡，并说明底图与文字排版各自来源。若下一轮要求给带字成品删字，应将该**成品**传给 `/v1/images/edits`，不要偷偷改为隐藏本地图层。
5. 若生图命令被审批拦截，不换工具或改写命令绕过门槛；明确报告“未生成/未发送”，等待用户授权。审批阻断不是模型能力失败。

## 飞书原生图片消息

- 常规回复：最终消息中放单独一行 `MEDIA:/absolute/path/to/image.png`（不要放代码块或反引号）。适配器上传并投递原生图片；先确认路径存在、可读。只发 Markdown 本地路径或“图在上面”不算交付。
- 若需要**立即显式发送并回查**：按 `lark-im` 和 `lark-shared` 的权限/消息约束，用 `lark-cli im +messages-send --as bot --user-id <当前用户 open_id> --image ./poster.png`（在图片目录执行；`--image` 本地文件用相对路径，或使用已有 `image_key`）。该命令先上传图片资源，再发 `msg_type=image`。底层对应上传 `image_type=message` 取得 `image_key`，然后发 `content={"image_key":"img_xxx"}`。不要把完整 token 或 base64 内容输出。
- 显式发送的验收：读取返回的 `ok:true` 和 `message_id`，再用 `lark-cli im +messages-mget --as bot --message-ids <id> --no-reactions` 回查 `msg_type=image`、非空 `image_key`。只能据此说**服务端发送并读回成功**，不能据此断言用户客户端已渲染；客户端问题须另取截图/线程证据。
- 如果实际没有执行生图或发送步骤，如实报“未生成/未发送”，不要声称“做好了”“发了”。
